## ML prospection for T3 (reference only, not incident facts)

| Finding | Source | Relevance |
| --- | --- | --- |
| XChainWatcher (2025): logic-driven rules on cross-chain bridges; authors state that training anomaly detectors on live "normal" bridge data is impractical because bridges are constantly attacked and never cleanly labeled. Detected Ronin ($611M) and Nomad ($190M). | https://arxiv.org/abs/2410.02029 | Validates our deterministic R1 approach for the bridge layer; argues against ML as the primary bridge detector. |
| HOUSTON (NDSS 2026): real-time, explainable anomaly detection using learned "likely invariants" between contract arguments and storage, plus call-path models; 94.8% TPR over 115 incidents. | https://www.ndss-symposium.org/ndss-paper/houston-real-time-anomaly-detection-of-attacks-against-ethereum-defi-protocols/ | Closest academic model to our need: learned invariants are explainable and vulnerability-agnostic. Requires transaction traces, which our collector does not have. |
| LSTM autoencoder + Isolation Forest ensemble, unsupervised, trained on pre-incident data only; evaluated on Compound DAI (2020): ensemble AUC 0.97, zero false alarms per day at precision >= 0.95. | https://exa.ai/library/publication/0cmhswbqck5 | Directly applicable pattern: train on normal lending-market metrics only, score the window, ensemble with a nonparametric baseline. |
| Forta Attack Detector: combines low-precision base alerts (heuristic and ML, including an Isolation Forest bot on token transfers) by attack stage; anomaly scores are multiplied per stage; critical only when the combined score is extreme. | https://docs.forta.network/en/latest/attack-detector-bot/ | Production-proven architecture for layering ML on rules: ML lowers noise and corroborates, rules stay authoritative. |
| Hypernative: ML models, graph analysis, heuristics and simulation; claims near-zero false positives and that 98-99% of attacks were detectable two minutes or more before the first exploit transaction. | https://www.hypernative.io/product/onchain-monitoring-automated-response | Industry confirms the hybrid approach; vendor claims are unaudited. |
| KelpDAO on-chain reconciliation (SQD): the forged delivery on Ethereum (block 24,908,285, nonce 308, 116,500 rsETH) was executed 12h38m before the genuine nonce-308 send on Unichain (0.001 rsETH). Largest legitimate send in pathway history: 1,000 rsETH; cumulative all-time: 30,479 rsETH. The bridge called `transfer` from custody, not `mint`. | https://sqd.dev/learn/kelpdao-rseth-exploit/ | Primary on-chain evidence. Shows the two robust detection signals: (1) a delivery whose source send does not exist yet, (2) an amount 116x the largest historical send. Both are logic/statistical outliers, not ML patterns. |
| BlockSec Phalcon: 200+ defined attack characteristics plus an "AI-based risky transaction early detection algorithm"; reports ~99% precision on high-risk alerts, zero false positives when combined with user rules. | https://blocksec.com/blog/ten-most-frequently-asked-questions-about-phalcon-block | Same hybrid architecture: rules are authoritative, ML scores risk. |
| Gradient boosting (XGBoost/LightGBM/CatBoost) is the dominant family in DeFi fraud and account-classification papers, evaluated with SHAP for explainability. | https://arxiv.org/pdf/2306.07972 ; https://www.mdpi.com/2076-3417/15/19/10841 | Supports LightGBM as the classifier choice when labeled sequences exist. |
